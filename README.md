# C++ BigInt 高精度大整数运算库

> 👨‍🎓 **写在前面 (Background)**：
> 这是我在大一（Freshman Year）时完成的一份 C++ 面向对象课程设计（Course Project）。
> 作为一个刚接触编程不久的新手，这份代码可能显得“又臭又长”，没有用到什么高深的现代 C++ 特性（如模板元编程、移动语义等）。但我尽力用最底层的逻辑、最直观的方式，把每一个边界条件、每一处内存分配都交代清楚。欢迎各位大佬指正！

## ✨ 项目功能 (Features)
* **基础运算**：实现了任意长度带符号整数的加法（`+`）、减法（`-`）、乘法（`*`）。
* **比较运算**：重载了 `==`, `!=`, `<`, `>`, `<=`, `>=`。
* **流操作**：重载了 `<<`，支持直接 `cout << a` 输出。
* **内存管理**：严格遵循 C++ **Rule of Three**（手写了析构、深拷贝构造、赋值重载），杜绝了内存泄漏和双重释放。
* **工程化**：附带 `Makefile`，支持 `make` 一键编译，代码通过 `g++ -Wall` 严格编译，**无任何 Warning**。

## 📂 关于测试文件 (About `main.C`)
仓库中的 `main.C` 是**老师提供的测试样例**，并非我编写的交互式程序。
这份测试用例极其暴力地涵盖了各种边界情况（超大数、跨量级加减、正负号交替、链式连续运算等）。我保留了这份原始测试代码，以证明本 `BigInt` 库在应对极端测试数据时的健壮性。如果你想自己测试，直接运行 `make` 即可看到结果。

## 🛑 设计约束 (Design Constraints) 与吐槽
你会发现这份代码的底层非常“原始”，是因为老师提出了极其硬核的要求：
1. **禁用 STL 容器**：强制使用 C 风格字符串（`char*`）和裸指针，禁止使用 `std::string` 或 `std::vector`。这也是为什么代码里充满了 `new` 和 `delete[]`。
2. **强制“人类可读”存储（大端序）**：算法竞赛中通常采用逆序存储（个位在 `s[0]`）。但老师强制要求高位在左、低位在右。这导致减法必须从后往前倒着借位，且手动清理前导零，使得代码量直线上升。

## ⚠️ 已知局限与“为什么没做” (Known Limitations & Why)

为了作业的安全性和逻辑完整性，我并没有实现所有的高精度功能，请理解大一新生的头发存量：

*   **关于除法（Division）**：
    本次作业没有实现大数除法。大数除法（长除法）涉及极为复杂的“不断试商、回退、再乘、再减”的回溯逻辑，且除法会导致小数产生。考虑到本次作业的核心考察点是**内存管理**和**基础运算符重载**，如果强行用 `char*` 手搓大数除法，容易掩盖掉对底层的练习。未来如果时间允许，我会学习并补充 `absDiv` 逻辑。

*   **关于类型转换（Type Conversion）**：
    目前仅实现了从常规整型（`int`）到 `BigInt` 的构造（主要是为了兼容 `BigInt zero(0);` 这种测试用例）。
    **我没有支持 `long long`，也没有提供反向的 `to_int()` 接口。**
    原因很简单：超大型整数本身就只有作为字符串存在才有意义。如果传入或转换为超出范围的类型，极易发生溢出引发未定义行为（UB）。我觉得让一个高精度库提供这种“高危且无意义”的接口是不安全的，因此只保留了最基础且安全的 `int` 转换，超大数请直接使用字符串构造（如 `BigInt("123456789012345")`）。
